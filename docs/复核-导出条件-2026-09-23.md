## 复核结果（2026-09-23 晚，Codex gpt-6-sol + DeepSeek 各一轮）

两边都报的、我回代码核实后**改掉**的：

1. **弹窗里的「到仓日期」跟列表那格不是一个口径**（超管 / 员工）。弹窗原来绑 `shipDate`（没有回退），列表那格绑 `arrivedAt`（没填到仓日期就退到建单日期）。到仓日期为空的单会出现「列表查得到、导出漏掉」。已把弹窗改绑 `arrivedAtFrom/To`。（只读查了线上：1776 张单里到仓日期为空的 **0 张**，所以目前还没发作；员工清空发货时间就会造出来。）
2. **列表两组日期都填时，带进弹窗只取一组**（`||`），导出会比列表宽。已改成取**交集**（起始取晚的、截止取早的），新增 `mergeDateFrom` / `mergeDateTo` 并加了测试。
3. **客户端导出没有「运单分组」**：客户切到「已签收」页签点导出，导的还是全部状态。已补上分组条件，打开弹窗时从页签带入，导出按分组拉数据。
4. **客户那份的列比管理员多一列「物流状态」**，跟老板「除了柜号，其他一样」对不上。已把管理员那份也补上这一列；顺带把管理员导出的「运输方式」从 `sea` / `land` 改成中文（列表里本来就是中文，只有导出没转）。现在两份逐列一致，只差柜号、客户列改叫唛头。
5. **测试能假绿**：列名正则要求冒号后有空格，写成 `柜号:x` 就抓不到；而且只查「客户少没少列」不查「多没多列」。已改成两边双向比、冒号后不要求空格、先去掉注释行。
6. **收尾**：删掉没人用的 `countShipmentFilters`（它的计数口径还跟弹窗里的不一致）；`productDim` 从员工端和客户端各一份合并到 `modules/staff/utils.ts`。
7. **客户端查询结果为 0 时看不到导出按钮**。已把导出面板抽成一份变量，「无匹配订单」下面也放一个，条件可以在弹窗里清掉再导。

核实后**没改**的：

- 客户接口返回 `receivableAmountCny`、`remark`：都是既有字段（客户自己要付的钱、客户列表本来就显示的备注），柜号后端已替换；本次导出两列都没写进去。
- 「只填截止日期时，没有日期的单也会被带上」：这是列表原本就有的口径，改了反而列表和导出对不上。
- `fetchAllPages` 50 页 × 500 = 25000 条上限：列表本身也走这条路，线上 1776 张，没到。
- 代理端那格写着「品名 / 国内单号」，但只有写在运单上的国内单号搜得到，写在产品行上的搜不到 —— 这是以前就有的，列表和导出一模一样；改它会顺带放宽代理端列表的搜索（产品行的国内单号默认值是「货拉拉」，搜中文会多出一堆），所以这次没动，先报给老板。
