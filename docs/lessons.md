## 2026-09-07：列数对了，不等于表头与数值视觉对齐

- th/td受内联和旧主题不同padding覆盖时，同列边界一致，文字仍会差4px；总箱数只给td右对齐而表头靠左，偏差更明显。数字列应成对标记表头/单元格并统一边距。
- 验收除了逐列值不变，还要用真实浏览器getComputedStyle与Range测文字右缘；覆盖三端、窄屏和滚动/勾选。只数th/td或看源码有right会漏掉这种问题。
- 几何回归要真实撤掉边距或表头标记看测试变红。页内局部值需从原AST一同装入渲染夹具，漏绑定属于夹具问题，不能算业务回归。

# 项目踩坑记录

## 2026-08-27：批量导入必须先按业务实体分组，不能把 Excel 行当成订单

- Excel 的一行可能只是同一运单的一种产品或一种尺寸。若前端逐行调用“创建运单”，同号第二行起只会触发唯一约束，最终留下每票第一条明细和错误的箱数、重量、体积。
- 正确顺序是“逐行解析与定位错误 → 按运单号分组 → 校验公共字段一致 → 汇总并一次提交 `products[]`”；后端仍应以产品明细为事实源重算整票合计，避免信任调用方传来的重复合计字段。
- 回归要同时断言三层：页面显示的原始行数/合并运单数、接口成功数、数据库订单/运单/产品数量与件重体守恒。只验证 Excel 被读出 300 行，并不代表300行被正确归入100票。

## 2026-08-26：运营工作台的层级优先用排版，不要用多套状态色堆叠

- WD、客户、地址本身已有三级业务层级；再叠加橙/绿左边框、彩色胶囊、彩色进度和实心页签会让同一屏出现过多视觉主角。运营密集界面应优先用字号、字重、留白和 1px 分隔线，颜色只保留给真正的主操作与危险操作。
- 全局 `button:not(...)` 背景规则会覆盖局部 `background: none`。手机菜单按钮因此变成蓝底，而三条菜单线也是蓝色，最终看成无含义的纯色方块。图标按钮要用更明确的透明背景覆盖，并在 390px 真机尺寸检查按钮与图标的计算颜色，而不能只看 JSX 结构。

## 2026-08-26：删除可选映射后，前端派生字段也要恢复服务端默认值

- 可选柜价记录删除后，服务端 GET 会回到默认币种 THB；若前端只把价格清空、仍保留原草稿的 CNY/USD，页面会短暂显示一个数据库里不存在的状态，直到刷新才纠正。删除成功时要同时归一所有派生默认字段。
- API 已下发的收件人姓名、电话、地址要在通用响应类型中完整声明；局部代码使用 `any[]` 即使运行正常，也会让未来字段改名时失去编译期保护。

## 2026-08-25：分组列表必须先算完整实体，再搜索；失败态不能伪装成空数据

- WD 是业务实体，内部有多票运单。若先按搜索词过滤运单行、再按 WD 分组，搜索到一张已签收运单会把真实 `1/3` 误算成 `1/1` 并显示“派送完成”。应先对完整 WD 计算客户、地址、签收进度，再用 WD 内任一字段决定整张卡是否命中。
- 列表需要明确区分“加载中 / 请求失败 / 数据确实为空 / 筛选后无结果”。请求失败时直接落入空数组会让用户以为生产没有数据；有旧数据时可显示刷新错误并保留缓存，无旧数据时只显示错误和重试。
- WD 级信息（司机、车辆、日期）只显示一次；客户级导出按钮必须从当前客户组直接传 `deliveryNo + clientId`，避免下拉残留选择把文件导给错客户。

## 2026-08-25：固定 XLSX 模板分页与分柜指标必须整体守恒

- **背景**：整柜清单和客户签收单直接填充用户确认的固定模板，运单还存在历史父子分柜数据。
- **现象**：拉伸行、动态合并或把多地址塞进固定行高备注会破坏版式；只克隆 worksheet 会漏工作簿元数据；逐票四舍五入或只用“子单是否为空”识别旧数据会让父子总重、总体积变多或变少。
- **教训**：超容量时克隆完整工作表并同步 workbook relationships、content types、extended properties；每页保持原列宽/行高/样式/合并/打印设置，跨页序号连续，“全局总计”和“页内小计”分开处理。多地址用独立站点页，不挤压模板行高。
- **教训**：分柜重量/体积必须以整个父子家族为单位，在 kg/m³ 的最小精度单位上累计分配并校验订单总量守恒；历史空值、父单回写整票、订单件数为 0、总量调低和循环小数都要有回归。
- **教训**：React 导出按钮使用的客户选择属于派生状态，搜索或刷新后必须重新对当前 WD 卡片的有效客户集合做校验，不能继续使用隐藏行留下的旧值。
# 2026-08-25：新增可选关联表未迁移，也会让整个列表查询 500

- Prisma `include/select` 了一个新关系时，即使关系业务上“可选”、表里计划先是 0 行，物理表不存在仍会让父表 `findMany()` 整体失败。
- 本地/部署验收不能只看 API 健康检查；要实际请求新增关系所在的页面接口，并检查迁移是否已执行。
- 历史迁移登记不完整时，不要用 `db push`，也不要直接跑全部 pending；先审核目标迁移 SQL，再只执行明确的纯新增迁移并登记 applied。

# 2026-08-25：客户导出要同时守住正文隐私与写接口公司边界

- 客户 XLSX 即使没有 `containerNo` 字段，`shipment.remark` 仍可能包含“装入柜子 XXX”；所有客户导出数据都要复用统一的正文净化函数，不能只靠模板不显示字段。
- 创建 WD 的 `shipmentId` 是外部输入；派送记录虽然写入当前 `companyId`，若不先按 `{ id, companyId }` 验证运单，仍会跨公司改原运单状态和轨迹。
- 多票创建必须在同一事务内先锁行、逐票验证归属再写；中途遇到跨公司运单时整车回滚，并用副作用计数回归证明没有部分提交。
