## 做了什么
- 后端新模块 `apps/api/src/modules/finance2-wallet/`：
  - `routes.ts` 三个代理专用的只读接口：`GET /agent/finance-wallet`（余额）、`…/ledger?cursor=`（流水，一页 100）、`…/withdrawals?cursor=`（提现记录）。
    代理编号**一律用登录的这个代理**（session-guard 每次从库里现读），不收页面传的编号；客户 / 员工 / 管理员 403。
    拿不到数据统一回 200 + state：`notConfigured`（没配地址密钥）/ `notFound`（财务 404，还没建档）/ `unreachable`（超时、连不上、5xx、密钥不对、格式不对）/ `ok`。
  - `views.ts` 按约定逐字段核对、逐字段挑出来（不整个转发）：金额必须是两位小数的字符串（可以负）、时间必须带时区、回的代理编号要跟问的一样、hasMore 跟游标要对得上；不认识的种类 / 状态照收、显示原值。
- 连财务的地址和密钥跟扣货名单**共用一把**（约定 10.0：物流拉财务只有一把）：`FINANCE2_HOLDS_SECRET` + `FINANCE2_API_BASE`。抽出 `finance2-holds/config.ts` 的 `readFinance2Remote()`，**不看扣货开关**——扣货关着，钱包照样能用；`client.ts` 的取 JSON 函数改名导出 `getFinance2Json`。
- 前端：`components/agent/AgentFinanceWallet.tsx`（三块余额：可用余额 / 待结算 / 已提现，流水表、提现记录表，「加载更多」翻页），菜单「我的钱包」→ `/agent#my-wallet`。只能看，没有申请提现按钮；金额照字符串显示、负数标红；时间按北京时间（跟代理端别的页面一样）。
- 原来那个「钱包」分区（`#wallet`）是**客户的集货余额**，名字本来就叫「集货余额」，2026-09-18 起对代理关着，没动。
