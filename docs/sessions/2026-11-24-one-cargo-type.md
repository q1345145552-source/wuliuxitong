# 2026-11-24 一票只有一个货型（不能单独产品选货型）

## 老板说的
- 「改一下逻辑，一票只会有一个货型，不能单独产品选择货型」（11-23 晚看完编辑运单弹窗后说的）。

## 查到的（线上只读）
- 原来每条产品行各选各的货型，整票记最严的（10-11 那条「混装排最严」）。能逐行选的地方：编辑运单（员工 / 超管共用）、员工两套建单（侧边栏「创建订单」+ 弹窗）、超管建单、客户预报、员工批量导入（同一票几行各填各的）、到货通知（每款一个）、整柜（清单每行一个 + 模板每行一格）。
- 线上 3347 张有产品行的单里，**101 票**一票里混着两三种（普货+敏感 49、商检+普货 36、商检+敏感 12、三种 4），最近一个月还在出（10-25～11-20 共 20 票），83 张已签收；另有 239 票产品行都一样、订单记的不一样（9-10 前老数据）。到货通知混着的 15 条，全是已转正式运单的。集货预报单：普通版 2 张 0 混、仓库版 9 张 1 混。
- 财务系统（finance-link / finance2）按产品行把货型和方数传过去：以后一票各行都是同一个。

## 做法
- 共用（`packages/shared-types/cargo-type.ts`）：`distinctCargoTypes`、`mixedCargoTypeIssue`（「一票只能有一个货型，现在这票的产品里有「普货」「敏感货」2 种」）、`waybillCargoTypeOf`（打开时整票显示哪个：有产品行看产品行，混着的取最严 = 原来整票记的；没有看订单的）。
- 后端：货型校验挪到 `orders/cargo-read.ts`（纯函数，routes.ts 转出去），新 `readOneCargoType`：产品行**填了的**不止一种 → 400「…这次没有保存。请刷新页面，在整票的「货型」里选一个」；只有一种就是它（整票那格不看 —— 老页面整票那格一直发默认 normal、产品行才是真选的）；都没填看整票；都没填 explicit=false。
  - 客户预报、员工建单（含两种批量导入）：整票 + 每条产品行都写成这一个。
  - 超管改单（员工也走这条）：请求里说了货型（产品行或整票）→ 就是它；只发产品行没带货型 → 沿用这票现在显示的；都没动 → 不碰。动了就订单 + **这票全部产品行** `updateMany`。原来「只改整票、跟产品行最严的对不上就报错叫去产品行改」去掉；原来货型单独第二次写订单去掉（跟别的项同一次、同一个 now）。
  - 收货（直接调接口改整票货型）：产品行跟着改。
  - 到货通知保存：每款不止一种 → 400；转运单 / 同步待入库：订单产品行统一写最严那个（上线前混着的老通知转出来不带混装）。
  - 整柜建 / 改：清单不止一种 → 400。
- 页面：编辑运单上面那排加「货型」（`<Named caption="货型">`，在运输方式后面）、产品行去掉货型那列；员工两套建单、超管建单、客户预报（不管分没分产品行都显示）、到货通知（「运输方式」前面）、整柜（「运输方式」后面）都只在整票选一次，提交时每行发它。批量导入：同一票几行填得不一样报错点名「第2行填的「普货」、第3行填的「商检货」…」，空着的行跟着填了的；模板填写说明第 13 条改了。整柜传表格：几行不一样 / 认不出来当场不读。
- **老单不改库**（9-17「不改线上数据」）：列表照旧把几种都列出来。编辑运单 / 到货通知里改已转运单 / 改整柜打开混着的老单时，红字写「这票原来几个产品的货型不一样（普货、敏感货）。一票只能有一个货型，保存后整票统一成上面选的「敏感货」」，**存一次就统一**（编辑运单「打开时的样子」货型记成空串，随便存都发货型；只发整票货型，不整份发产品行 —— 不顺带改总重量总体积，教训 33）。到货通知「打开时的样子」（base）照库里原样发（`rowCargoAsStored`），不然混着的老通知一存就被当成「同事改过货型」。
- 没动：集货预报单（普通版 / 仓库版）照旧每个产品选货型 —— 那边是集货、不是运单，仓库版按货型算钱；显示 / 导出（多种时「普货 / 敏感货」并排）不动。
