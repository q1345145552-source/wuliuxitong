## 没刷新的老页面（上线那一刻还开着 11-24～11-26 那版页面的人）
那版页面是「一票一个货型」：保存时把每一行 / 每一款的货型都发成同一个。改回去的后端照存的话，同事特意分开选的货型会被悄悄改成同一种（CLAUDE.md 第 45 条第⑤点）。逐条路的结论：
- 老页面建单、建整柜、新登记到货通知：每行发的是同一个货型，库里没有老数据可盖，照存，没问题。
- **改单接口 `/admin/orders/update`**（编辑运单弹窗、到货通知「修改已转运单」）：现在的两个页面请求里带 `cargoPerRow: true`（请求类型里写成必填；到货通知那边由 `buildAdminOrderPatch` 算完「有没有改动」之后带上）。拦截（`admin/routes.ts`，锁订单、核版本号之后、写库之前）：**没带标记** ＋ 库里这票产品行不止一种（按原样数）＋（发来的每条产品行都明写着货型且全是同一种，或没发产品行只带了整票货型）→ 400「这个页面不是最新的…请刷新页面后再改」。
  - 第一版只认「带了整票货型」的（现在的页面不发这一项）。收尾一轮 Codex 第 3 轮 / dsh 第 4 轮同一条必须修：库里是 普货 + 认不出来的老值（或大小写不一样、空串）时，那版页面把它们都当普货、以为只有一种，改产品行时不带整票货型、每行发普货，第一版照不到 → 改成认标记。
  - 没发产品行、整票货型刚好等于最严那个的也拦（dsh 第 1 轮必须修）：老弹窗存成功一次就不再带整票货型，下一次改产品行就认不出来 —— 混着的单在老页面上一次都不能存成功。
  - 「几种」按库里原样数、不先校验货型值（dsh 第 2 轮）；直接调接口、产品行各写各的 / 没每行都写货型的照原来的规矩走。
  - 只有一种货型的单上「只改整票、对不上」那句老 400 照旧，提示后面加了「先刷新页面」。
  - 有意的取舍：11-24 之前就开着的页面也不带标记，它特意把混着的改成同一种（包括删到只剩一行）也会被拦、叫刷新。
- **到货通知保存 `/staff/arrival-notices/save`（改已有的）** 和 **整柜修改 `/staff/fcl-containers/update`**：老页面发的跟现在的页面「特意改成同一种」一模一样，后端分不出来（Codex 第 1 轮必须修 1、2）→ 现在的页面请求里带 `cargoPerRow: true`；没带这一项、库里货型不止一种、这次发来的却不超过一种 → 400 叫刷新。到货通知排在 base 比对之前（已转待入库的也就不会盖到订单产品行上），整柜排在版本号核对之后。「库里几种」都按产品行原样数（到货通知原来按归一后的数，普货 + 认不出来的老值会被数成一种放过去，Codex 第 2 轮必须修 1 / dsh 第 3 轮）。有意的取舍：11-24 之前就开着的页面也不带标记，它特意把混着的改成同一种也会被拦、叫刷新（刷新后能改）。
- **批量导入旧模板**（Codex 第 1 轮必须修 3）：11-24～11-26 下载的员工模板「填写说明」第 13 条写着「空着的跟着填了的那行」，现在空着 = 普货。员工页读表格时认出这份旧模板（随便哪张工作表里有这句话，不看表名，Codex 第 2 轮）就整份不读、提示重新下载模板（`batchOrderImport.ts` 的 `oldOneCargoTemplateIssue`）。管理员页的批量导入是另一张模板、客户批量下单模板 8ee373f 都没改过说明，不用管。认不出来的情况：有人把说明那张表整张删了、把那句话删了 / 改写了、或把明细另存成只有明细的文件。
